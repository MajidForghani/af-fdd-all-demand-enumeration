# AF-FDD definitive benchmark design

## Scientific question

The study tests whether arc-coordinate AF-FDD is preferable when binary-path multiplicity is large relative to frontier complexity, while allowing Bai-2021 and Yeh-2024 to remain competitive on instances with a small path basis. It is not designed to force an “AF-FDD always wins” conclusion.

## Frozen collections

### Synthetic core: 1,200 instances

The full factorial design is `6 families × 4 sizes × 2 capacity regimes × 25 replications`.

| Factor | Levels |
|---|---|
| Family | sparse DAG, dense DAG, sparse cyclic, dense cyclic, layered/path-rich, directed mesh |
| Vertices | 10, 14, 18, 22 |
| Capacities | small: discrete uniform 1–2; moderate: discrete uniform 1–5 |
| Replications | 25 independently derived seeds per cell |

Sparse/dense arc counts are approximately 1.7n/2.8n for DAGs and 2n/4n for cyclic digraphs. A draw is accepted only if its underlying undirected graph is connected and at least one ordered terminal pair is reachable. The source–sink pair is sampled uniformly from all reachable ordered pairs *after* the graph is drawn. Vertices are then relabeled so source is 0 and sink is n−1, and arc order is independently shuffled. Layered and mesh families are generated by documented constructive models and use the same capacity assignment and relabeling principles.

This adapts the supplied random-network guide rather than copying its undirected minimal-cut design. We retain factorial stratification, conditioned generation, post-generation terminal selection, fixed stored order, deterministic seed derivation, calibration by whole cells, process isolation, and raw-data retention. We change the graph models because all-level d-MP enumeration is governed by directed cycles, path multiplicity, capacities, and frontier width.

### SNDlib-derived robustness collection: 72 instances

Abilene, Polska, and Nobel-US are included. For each topology, three terminal pairs are selected deterministically by the number of simple undirected paths (few, median, many). Each pair receives two directed transformations:

- `acyclic`: orient links by increasing BFS distance from the source, with deterministic tie breaking;
- `bidirected`: replace every link by two opposite arcs.

Four capacity profiles are used: unit, U{1,2}, U{1,2,3}, and U{1,…,5}. Thus `3 × 3 × 2 × 4 = 72`. These are SNDlib-*derived* two-terminal multistate cases, not claims that SNDlib itself supplies this exact reliability model.

## Reproducibility

- Master seed: `2026101901`.
- Per-instance seeds: first 64 bits of SHA-256 over the master seed and factor labels.
- PRNG: Python `random.Random` (MT19937).
- Every complete instance, including arc order and capacities, is stored in JSONL and SHA-256 hashed.
- The manifest records rejected-draw attempts.
- No instance may be regenerated after seeing algorithm outcomes.

## Outcomes and protocol

Each algorithm runs in a fresh process. The worker performs one untimed tiny warm-up, then measures preprocessing, enumeration/diagram construction, explicit-output traversal, total wall time, and peak process-tree RSS. Default limits are 600 seconds and 12 GiB per run. Repetition 0 is run for every algorithm-instance pair; repetitions 1 and 2 are run only if repetition 0 succeeds. A median is reported only for pairs completing all three successful runs. First-run timeouts and memory/path-limit failures remain solved-count evidence but are not redundantly repeated. Binary-MP generation is included for Bai-2021 and Yeh-2024. AF-FDD’s order selection is included.

The explicit mode computes an order-independent 128-bit two-accumulator digest and output count. Equal digests and counts are a strong engineering check; small cases should additionally be checked by exact sets. Count mode is reported separately and must never be compared as if it had paid explicit-output cost.

Primary reports: solved counts, median and geometric-mean times, speedups on common solved sets, performance profiles, peak RSS, and strata by binary-path count, empirical AF-FDD width, family, cycles, capacity regime, and output count. Timeout values are not imputed as ordinary run times.

## Required staged execution

1. Generate and freeze the corpus.
2. Run one repetition on a stratified calibration subset (at least five complete replications per cell). Calibration may change global limits or remove entire predeclared cells, never individual hard instances.
3. Run a no-`tracemalloc` AF-FDD ablation on the same calibration subset.
4. Freeze software, limits, and analysis rules.
5. Run the definitive three-repetition study, using shards if needed.
6. Inspect output disagreements before interpreting speed.

## Separate held-out challenge collection

The balanced corpus is retained in full. A second, independently seeded
path-rich challenge design targets practically nontrivial cases without
selecting individual instances by observed runtime. Its 204-case pilot is used
only to select whole predeclared cells; all ten held-out replications from an
eligible cell are then evaluated. The fixed design and selection rule are in
`CHALLENGE_CORPUS_PROTOCOL.md`. Balanced and challenge findings are reported
separately.

The proposed selection indicator starts with `binary_paths / max(1, frontier_width)`, but its usefulness and any threshold must be estimated using nested cross-validation or a held-out subset. It must not be chosen and evaluated on the same observations.
